## Challenges

- **Duplicate delivery:** Network jitter can deliver an event more than once, so consumers need idempotency based on an event identifier.
- **Brief disconnections:** After recovery, the boundaries around resubscription, replay, and message ordering must be explicit.
- **Processing backlog:** When downstream processing slows, queue depth needs monitoring and a backpressure policy.

## Solution

The demonstration uses an event ID as the idempotency key and expiring state records to avoid duplicate processing in a short window. Events requiring strict order are partitioned by vehicle identifier; events without a global-order requirement can be consumed in parallel. The real design must weigh QoS, storage capacity, and business consistency requirements.
