# GitHub Pages 子路径路由修复设计

## 目标

当站点部署在 `https://blog.colemak.cn/brief/` 时，所有站内导航、语言切换、首页跳转与 404 回退都保留 `/brief/` 前缀；本地开发仍从 `/` 访问。

## 设计

- 保持现有部署配置：GitHub Pages 工作流已经由 `BASE_PATH` 注入 Astro 的 `base`，普通仓库构建为 `/brief`，未设置时保持 `/`。
- 保持现有 `path()` 作为唯一的基路径拼接入口。它已经为页面组件生成的链接添加 `/brief`；不得让 `localizedPath()` 再拼接基路径，以免生成 `/brief/brief/...`。
- 修复遗漏该入口的两个边界：根页的客户端语言重定向，以及旧单语言页面使用的 `LegacyFallback`。两者都通过 `path()` 生成目标地址。

## 验证

- 构建测试使用 `BASE_PATH=/brief` 生成产物，并验证首页语言跳转及旧路由回退包含 `/brief/zh/`。
- 默认根路径构建仍验证为 `/zh/`，防止本地开发回归。
- 保留现有根路径构建测试，防止本地开发回归。

## 非目标

- 不改变 URL 结构、内容路由或语言选择策略。
- 不修改未跟踪的其他 `docs/` 内容，也不提交本说明文件。
