# 项目实战问题博客草稿设计

## 目标

在技术主页的中文博客内容目录中，为 28 个来自近期项目实践的主题创建独立草稿。每篇只提供经过脱敏的标题、概要和后续补充提示，供作者补齐证据、解决步骤与复盘；不把内部地址、车辆标识、客户信息或未证实结论写入公开内容。

## 范围

- 新建位置：`src/content/blog/zh/`。
- 文件格式：MDX，每个文件使用稳定、描述性的 kebab-case 文件名。
- 发布状态：所有新文章均设置 `draft: true`，不会进入公开列表、路由或站点地图。
- 不创建英文镜像，也不修改现有文章、项目页、站点配置或构建逻辑。

## 每篇文章结构

每篇文章包含：

1. Astro 内容集合要求的 frontmatter：`title`、`description`、`publishedAt`、`tags` 和 `draft`。
2. `## 概要`：说明问题场景、核心误区和可复用的方法，但不叙述可识别的线上事故细节。
3. `## 待补充`：提示作者补充背景、现象与影响、排障证据链、解决方案、验证结果、边界与复盘。

- 恰好创建 28 个新的中文 MDX 草稿。
